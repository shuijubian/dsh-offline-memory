# dsh-offline-memory

给会话一份**会淡忘、能打捞**的外置记忆。上下文被压缩或清空后，它不"复活"，而是**接上**。

## 三层存储（v1.1 架构）

| 层 | 文件 | 作用 |
|---|---|---|
| **底层存储** | `journal/seg-*.jsonl` | 全部会话原文，带日期索引，负责"接续" |
| **优化存储** | `optimized.jsonl` | 虚拟上下文里被评分压缩过的内容**长期备份**，带日期索引，是打捞来源 |
| **虚拟上下文** | `vctx.json` | 智能体的**临时记忆**：会淡忘删除，删了还能从优化存储捞回来 |

关键规则：

- **评分即衰变期**：评分低衰变快（最短 `minDecayDays`），评分高衰变慢（最长 `maxDecayDays`），评分 ≥ `scoreMid` 永久。
- **唤醒间隔必须 ≤ 最短衰变期**（服务端会强制压回），否则条目会在写入优化存储之前就衰变掉，接不上。
- **打捞只从优化存储取**，捞回来的条目进虚拟上下文并标注「原本生成日期 + 打捞日期」，自然衰变；**不回写优化存储**（那里已有备份）。
- **需要细节时**回底层存储按日期与前后文补全。

## 唤醒机制（取代"存档周期"）

唤醒 = 统一做延迟打分 + 淡忘清理 + 自动存档。可设：每几天唤醒一次、唤醒时段（支持跨零点）、软件开启时自动唤醒一次、自动存档开关；也能随时点「现在唤醒一次」。

## 评分器

| 项 | 选项 | 区别 |
|---|---|---|
| 主体 | **托管**（内置规则） | 零成本零延迟、完全离线；读不懂反讽与上下文 |
| | **会话智能体接管** | 用当前会话模型打分，更懂上下文；每条多一次模型调用，失败/超时自动回退托管 |
| 模式 | **即时打分** | 进来就打，虚拟上下文立刻最新 |
| | **存档 / 唤醒时一起打分** | 先只落底层，存档或唤醒时批量补分；省调用，但之前打捞不到 |

接管模式的坑：推理型模型会先花 token 思考，输出预算给小了会**只出思考、不出正文**（实测 24 token 时 20 次全空）。默认 160 token 就是为这个留的。

## 目录（各文件职责）

```
package.json       bundle 清单；main=lib/host.js，client=client.js
cordis.patch.yml   插入加载器的一行
lib/host.js        宿主接线：采集 / 注入 / 定时 / bootstrap 调度
lib/api.mjs        设置页接口（18 个端点，含管理/清理/读档）
lib/config.mjs     config.json + sessions.json；生效判定 = 总开关 AND 会话开关
lib/store.mjs      三层存储 / 淡忘 / BM25 打捞 / 读档 / 清理 / 快照
lib/bootstrap.mjs  首次开启全量入档（幂等、分块、可续传、超限降级）
lib/decode.mjs     解会话日志（多帧 zstd → JSONL → 消息 + 标题）
lib/score.mjs      内置评分器（rate / mood / trait / alignment / 好感 / Q&A 样本）
lib/stat.mjs       CLI：node lib/stat.mjs [sessionId]
client.js          设置页：总览 / 启用会话 / 存档设置 / 人设属性
test/smoke.mjs     冒烟测试（45 条断言）
legacy/            上一版实现，留档
```

## 设置页

- **总览**：总开关 + 状态。
- **启用会话**：选择要启用的会话（显示**标题 + 工作区**，不是文件名）；每会话独立的采集/注入开关。
- **存档设置**：全局参数（容量、注入预算、衰变期、存档周期、快照保留）+ 四个会话操作：
  - **读档**：选另一个智能体的档，把它的优化存储接到当前会话（只导入，不合并回去）
  - **存档**：补齐日志里没入库的内容并拍快照
  - **回滚**：回到最近一次快照
  - **管理存档**：三层各自的用量 / 条目 / 文件位置 / 打开预览 → **清理存储**（按"清理多久之前"删，两层确认）
- **人设属性**：心情、好感度**两个独立卡片**；萌属性有综合判定并可展开全部轴；阵营九宫格。

## 数据布局

```
${DSH_HOME}/offline-memory/
├── config.json            总开关与全局默认
├── sessions.json          会话注册表
└── sessions/<key>/
    ├── journal/seg-0000.jsonl   底层存储
    ├── optimized.jsonl          优化存储（长期备份 / 打捞源）
    ├── vctx.json                虚拟上下文（临时记忆）
    ├── important.jsonl          score≥7 的镜像
    ├── system-snapshot.json     开启时的 system prompt（脱敏后入档）
    ├── bootstrap.json           全量入档状态机与游标
    ├── snapshots/<ts>/          回滚点
    └── state/                   心情 / 好感账本 / 萌属性 / Q&A 样本
```

## 用法

```bash
node lib/stat.mjs              # 所有会话的三层统计
node lib/stat.mjs <sessionId>
node test/smoke.mjs            # 45 条断言
```

## v1.1 的真实边界

已实现：三层存储与迁移、评分即衰变期、存档周期硬约束、打捞（双日期标注、不回写）、读档、管理/清理（两层确认）、bootstrap 幂等续传降级、BM25 检索、注入预算、隐私脱敏、快照回滚、内置心情/好感/Q&A 样本/萌属性/阵营。

**未实现，别当成已有**：

- **人设编辑**：人设属性页目前只读展示，没有"人和智能体都能编写"的编辑与落盘。
- **评分器仍是内置确定性启发式**，不是"由会话所属智能体亲自评分"。改成模型评分要给每条消息加一次模型调用，会明显拖慢对话；接口已按三路输出（权重 / 心情好感 / 是否入 Q&A）预留。
- 摘要仍是**首句截断**，不是 LLM 压缩。
- 萌属性只覆盖 20 个可稳定触发的轴，其余保持 50 基线。
- 无倒排索引文件（BM25 在内存现算）；无跨进程写锁。
